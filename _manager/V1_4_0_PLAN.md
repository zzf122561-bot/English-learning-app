## 统一界面规范

设计方向：深蓝与银白的阅读界面，正文优先、操作独立；不用装饰性仪表盘、无意义英文标签或全页卡片套卡片。

| 角色 | 色值 |
|---|---|
| 深色文字 | `#16243B` |
| 主操作蓝 | `#315DA8` |
| 浅蓝选中面 | `#E8EFFB` |
| 页面底色 | `#F5F7FB` |
| 内容面 | `#FFFFFF` |
| 次级文字 | `#5F6D80` |

边线用低对比蓝灰；危险操作用红色，不作为普通强调。总控根主题提供完整Material色阶，避免默认紫色混入。中文界面/按钮用系统SansSerif；英文文章标题可用Serif，最多两行，不能挤压操作。界面正文16sp、次级13–14sp、按钮14sp；文章正文保留用户现有字号档位。用户字体缩放优先，不以强制缩字解决换行。

间距4/8/12/16/24dp；手机水平留白20dp（紧窄屏可16dp），内容面圆角16dp、轻边线，触点至少48dp。平板正文居中限制约720dp宽。安全区按宿主已消费inset处理，不重复添加两遍底栏留白。标志性元素为独立细蓝段号标记；禁止把段号、TARGETS、朗读按钮和首行正文挤成一行。

```text
                        [播放/暂停/继续全文]

英文自然段正文。目标强调保持原语义。

[显示/隐藏本段中文]   [播放/暂停/继续本段]

```

草图表达分区，不要求固定Row。窄屏、大字号、长标题优先换行，主要播放仍直接可见。首屏不被插画、大标题或模型说明占满。根主题是正式宿主配色来源，模块不得用嵌套MaterialTheme覆盖宿主全部颜色；独立测试可有内部fallback，不引入跨功能依赖。

## 功能1：书架与阅读

仅改`feature-01-word-memory`：
- 书架区分标题、导入主操作、文章列表；列表分层显示标题/真实学习进度/继续学习/次级菜单。保留导入、重命名、删除确认与状态。
- 阅读标题、工具、段落元信息、正文和段后操作分区；保留全文播放与字号、更多菜单“生成全文”。原段落生成/选择动作移到独立次级行或菜单，单句和指定范围能力不取消。
- 本段播放槽与译文显隐相邻、支持FlowRow；状态由宿主注入，不猜音频是否存在。正文使用完整可用宽度，长标题和大字不能遮住按钮。
- `readingContent`底部槽仍最多180dp。语音自行折叠次级内容并展开全屏播放器，不以增高底部槽压缩阅读正文。
- 公共回调/槽签名、DOCX/去编号、长按查词、默写、十档字号、显隐、阅读位置、Room 2/MIGRATION_1_2不变；不重写已验证parser/cleaner，不读Skill。

## 语音：紧凑播放条与沉浸页

仅改`experiments/tts-device-probe`，两个宿主继续复用Library。

- 阅读底部紧凑播放条可点击展开全屏播放页，展示实际播放文章/段，不把仅选中的范围当正在播放。展开/收起共用同一Media3 Session/Player；返回只收起，不暂停/取消任务、不新建Activity、不重置阅读位置。
- 全屏含收起入口、文章标题、第N段/共M段、当前段可读英文摘要/正文、真实进度和已播/总时长、拖动进度、上一段/播放暂停/下一段、倍速及片段列表。横屏/大字可滚动，主要播放操作可达。
- “章节/片段”先对应App现有自然段。列表显示原段号、开头摘要、已生成/生成中/缺失/失败、正在播放状态；不显示内部ID或缓存路径。选择目标段可播放。
- 用户选择本段仍只播本段；全文模式上一/下一或列表切段继续全文序列。缺失音频沿用先确认生成、补齐等待/仅已有跳过，不静默生成、不越过用户暂停。
- Seek使用实际duration，不编造逐字/逐句高亮时间轴；倍速沿用已验证范围，作用同一Session，不重新生成。音频焦点/耳机拔出/通知栏/锁屏状态同步。
- 生成与播放继续独立；生成摘要保留进度/暂停/继续/取消，管理/删除/导出放折叠详情或对话框，不把所有操作堆进180dp。关闭沉浸页不影响后台队列。
- 语音设置仍只管理模型、音色、风格和高级参数，按“当前模型/声音与风格/高级参数”分区，解释按项展开。不得放独立文章生成器/播放器，不擅改默认或已保存设置。

优先保持公共签名，由Library内部全屏Dialog/Compose层承载；若确需新宿主契约，先一次报告具体缺口，由总控决定，不读取功能1实现。

## 速度：证据与本轮实施

总控当前源确认：Qwen3-TTS 1.7B CustomVoice Q4_K_M走CPU ggml；CMake显式关闭GPU/NPU后端、OpenMP/KleidiAI，Android为通用armv8-a。持久队列已复用模型，并非每段重新加载。SOURCE_MANIFEST第9节旧样本34.08秒音频/RTF4.71约合160秒生成（按舍入RTF估算），加载约2.25秒；不是本轮设备测速。16GB内存不消除逐token计算量。

允许定向改现有性能路径及模块CMake/JNI/测试，不改变正确性、安全分片、取消、原子保存、有限重试、串行模型所有权、音色和权重：
1. 使用现有指标区分加载/预填充/token生成/解码写入/重试，补缺失的可比较摘要，不记录用户全文。修可证实的重复计算/分配/加载，不大规模重写。
2. 检查固定ggml对ARM dotprod/i8mm的构建与运行时分派，允许实现有能力探测和通用CPU回退的优化。禁止整库无条件新指令导致旧机SIGILL；当前架构不能安全隔离时报告限制并保持通用构建，不引入未审计动态下载/依赖。
3. 独立测试入口增加同一小段/同配置4/6/8线程对照（受设备上限约束）、冷/热区分，报告RTF/时长/内存/可获取的温度及实际后端；用户主动启动，不在正式App自动跑长基准。默认4线程不凭推测调大；不并行多段争用模型，不截短正文/降低上限伪装快。
4. 更快模型只做接入可行性与A/B接口说明：Kokoro-82M+sherpa-onnx有Android示例，Pocket TTS 100M有CPU/流式实现。候选不是已批准替换；Kokoro语音前端/依赖许可另审，Pocket代码MIT但权重CC-BY-4.0且官方获取有门槛，不统称全链宽松许可。先保留当前音色，不自行接云端/更换权重。Supertonic已2026-09-09归档，不作为长期主路线。

一手来源：[Kokoro](https://huggingface.co/hexgrad/Kokoro-82M)、[sherpa Android](https://k2-fsa.github.io/sherpa/onnx/tts/apk-engine.html)、[Pocket TTS](https://github.com/kyutai-labs/pocket-tts)、[Pocket权重](https://huggingface.co/kyutai/pocket-tts)、[Qwen](https://github.com/QwenLM/Qwen3-TTS)。均非本机测速。GPU/NPU/新模型若需新依赖或后端重写先报告，不套用其他手机/电脑倍数。
