### 2026-08-24：App v0.3.0 test.001 主文档 403

状态：`confirmed_device_failure`。证据来源为用户本人提供的 Android 实机截图；截图不复制进 Git，仅保留可审计事实。

当时观察到：

- App 已运行并进入底部“词典”入口。
- 搜索框内容为 `another place`，页面标题同步显示该查询。
- Collins 与 Oxford 两个结果标签均已显示，说明内置词典登记、查询协调和结果选择至少已运行到正文展示之前。
- 选中词典的正文区域由系统 WebView 错误页替代，地址为 `data:text/html;charset=utf-8;base64,`，错误为 `net::ERR_HTTP_RESPONSE_CODE_FAILURE`。
- 用户没有在本次反馈中确认覆盖安装方式、旧数据、功能1、返回导航、管理、导入、图片或发音；这些项目不得提高验收级别。

总控当时的增量诊断：

`SecureDictionaryWebView` 使用 `loadDataWithBaseURL()` 加载应用生成的词条文档。当时 `SecureDictionaryWebViewClient.shouldInterceptRequest()` 对任何不能解析为 `https://dictionary.local/<安全资源路径>` 的请求直接返回 403。该设备把主文档请求呈现为 `data:text/html;charset=utf-8;base64,...`，因此主文档也落入 403 分支，WebView 显示 `ERR_HTTP_RESPONSE_CODE_FAILURE`。这是总控依据截图与当时源码得到的直接因果诊断；当时修复后的真实显示仍需用户用 test.002 复测。

当时的候选处置：

- v0.3.0 test.001 判定用户验收不通过，永久保留原 APK 和哈希，不覆盖、不删除。
- 当时不创建 `app-v0.3.0` 标签；后来是 test.002 获用户验收后提升正式版，不改变 test.001 的失败结论。
- 功能2修复目标为 v0.1.1，App 仍为 v0.3.0，下一产物序号为 test.002。
