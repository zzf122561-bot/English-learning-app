- App 1.0.0 test.001已在用户设备上确认词典应用内链接“还是不行”，该候选永久判定不通过。
- 用户明确要求：“直接取消所有应用内链接限制”。
- 本轮不再以枚举少数安全锚点、路径或链接格式作为兼容策略；当前受控词典文档内部应默认放行。
- 总控无Android设备、无设备日志、无具体词条或原始链接标记，不得伪称已复现。

## 新的内部链接规则

### 1. 词典文档内部默认放行

- 当前词条HTML发出的同文档锚点不再按片段字符、编码、长度、路径形态或固定白名单拦截；交给WebView原生滚动。
- 解析到受控 `https://dictionary.local` 源的页面、片段、查询和MDD资源请求，不再因为未知路径、query、fragment、扩展名或链接形态直接返回403。
- 相对链接、绝对同源链接、`entry:`、`bword:`、词典自定义内部链接及经DOM动态生成的内部链接必须可工作；交叉词条仍在当前词典结果中替换查询，不给QUICK_LOOKUP增加返回层。
- 不能再把“未被枚举识别的词典内部链接”等同于恶意外部导航。

### 2. 允许词典自身脚本驱动链接

- 先只读检查两本授权词典真实词条的快捷链接结构，不记录正文，只记录链接机制、scheme、标签/事件类型和是否依赖脚本。
- 若词性定位依赖 `onclick`、`javascript:`、内联脚本或MDD内置脚本，应在本受控词典WebView中启用所需JavaScript能力并相应放宽词典文档CSP；不得继续以“JavaScript默认关闭”为由让内部链接失效。
- 必须支持MDD脚本资源按需读取，但不得新增JavaScript Bridge/`addJavascriptInterface`、弹窗、多窗口或跨App能力。
- 若真实链接不依赖脚本，不为追求改动量而无条件新增额外能力；审计文档写明实际机制和最终选择。

### 3. 仍保留的应用边界

- 外部 `http://`/`https://` 网页不在词典WebView内加载；本轮不新增外部浏览器跳转。
- `file:`、`content:`、`intent:`、`android-app:`、本地文件访问、内容提供者访问和跨应用启动继续阻止。
- `allowFileAccess`、`allowContentAccess`、file-URL跨域访问、多窗口和JS Bridge继续关闭。
- MDD资源仍必须来自当前已打开词典，不能访问App私有目录中的任意文件；资源大小和取消/关闭边界保持。
- 顶部/正文发音、MDD→HTTPS→TTS顺序、逐词典字号、Room v2和功能1导航均不得退化。

## 验证门槛

- 用合成HTML覆盖：普通/编码/空片段、相对和绝对同源链接、不同路径/查询、`entry:`/`bword:`、DOM动态链接、需要脚本的快捷定位。
- 证明所有受控词典内部链接不会进入blocked/403路径。
- 证明交叉词条只替换当前结果；同文档定位不改变查询、不增加返回层；QUICK_LOOKUP一次返回仍成立。
- 证明外部网页、`file:`、`content:`、`intent:`、跨应用和任意本地文件读取仍被阻止。
- 对两本真实词典各至少验证一类实际存在的快捷链接机制，只记录结构和通过/失败，不记录正文。
- 复跑功能2全部既有JVM测试、Android测试源码编译和AAR构建；功能目录APK=0、JNI=0。
- 公共 `DictionaryFeature(...)` 签名不变；`englishapp_dictionary.db`保持Room 2和既有 `MIGRATION_1_2`。
