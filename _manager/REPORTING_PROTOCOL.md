# 项目子 Agent 交接与汇报协议

## 派工前写明回复规则

总控必须先将下列内容写入子 Agent 可读取的 `MANAGER_LINK.md`、本协议或持久简报，再发送任务；已有字段通过引用复用，不要求每次新建文件。

- 回复对象：本项目“总纲”，任务 ID `01a024cb-1fba-7b23-a357-67eb2ad592b4`。
- 任务范围与结束条件：功能 ID、目标版本/里程碑、允许修改和读取的精确路径、完成标准。
- 完成交接：完成摘要、修改路径、对应来源版本或差异范围、已有核验结果及证据、未覆盖范围、数据库/公共契约变化、风险与需要总控执行的动作。
- 例外：测试失败、阻塞、授权不足、路径误读、公共接口或数据兼容变化、设备失败反馈，应及时一次性报告；不得擅自扩大权限或宣称完成。
- 交接后状态：按简报约定停止或进入下一项已授权工作；没有后续授权时等待总控，不自行增加工作。

子 Agent 只向本项目总控发送工作消息，协作需求也交由总控转达。跨项目只有管理员之间通信，子 Agent 不跨项目发消息，不互相派工。

## 必须汇报的事件

- 功能版本开发完成；
- 数据库、公共契约或受保护基线变化；
- 模块测试完成、失败或出现阻塞；
- 需要总控生成测试 APK；
- 收到设备测试或用户确认结果。

## 固定格式

```text
[FEATURE_MILESTONE]
功能 ID：
目标版本：
状态：milestone_passed / compatibility_gate_passed / ready_for_integration / blocked / contract_change / user_feedback
完成摘要：
修改路径：
证据对应来源：提交 / 差异范围与版本（功能任务无需执行 Git，可由总控登记）
测试命令与结果：
证据位置与未覆盖范围：既有日志/报告路径或本消息内足够清晰的结果
数据库迁移：无 / 说明
公共契约变化：无 / 说明
已知风险：
请求总控动作：
```

功能对话通过 Codex 跨对话消息发送到 `MANAGER_LINK.md` 登记的总控任务 ID。发送失败时，原文写入功能目录 `MANAGER_OUTBOX.md`，并保持“待总控接收”状态。

## 总控接收与等待

- 总控阅读交接即可接收已完成的核验，不要求重新打开全部日志、复算同一产物哈希、重复读代码或复跑已通过测试来“确认 Agent”。清晰的结论、适用范围和证据足以沿用；不强制为消息中已有证据另建审计文件。
- 只有新变更、失败、范围缺口或证据不足时，才在现有记录中说明原因并补充相应核验。集成新接线、冲突解决和新 APK 属于新增范围，所需检查由总控完成；已有模块结果继续复用。
- 接收后按需要完成本地提交/合并、App 集成、构建、归档和用户验收交付；不是每次状态汇报都启动整条发版流程。
- 总控派工后可结束当前回合等待主动回复，不轮询等待结果、不催促、不要求纯确认消息；用户明确要求进度或存在具体异常时再查询。
- 同一里程碑一次完整报告即可；后续仅报告新增结果或状态变化。发送失败才使用 `MANAGER_OUTBOX.md`，并标明交接未完成。
- `github-sync` 沿用上述通信与等待规则，推送交接字段与异常处理以其已授权的 `GITHUB_SYNC_POLICY.md` 为准；不要求它使用功能版本报告模板。
