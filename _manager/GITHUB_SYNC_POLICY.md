## 权限原则

1. 本地 Git 是项目修改和历史记录的主来源。
2. 项目源码、文档、版本与发布记录必须先由总控检查并提交到本地 Git。
3. 创建同步任务、登记远端或完成只读检查，不等于授权 push。
4. 只有用户明确要求更新 GitHub 后，总控才能向同步任务发送本次同步指令。
5. 一次授权在成功或失败回报后即结束；失败后不得在网络恢复时自动补传，重试需要用户再次明确授权。
6. 同步任务不得自行开发、编辑文件、创建提交、合并、变基、创建标签或改写历史。
7. 默认只允许把总控明确列出的一个或多个本地分支或标签普通推送到登记远端。

```text
本地引用：<branch-or-tag>
期望提交：<full-sha>
远端引用：<branch-or-tag>
允许创建远端引用：是 / 否
允许强制推送：否
允许删除远端引用：否
```

缺少“用户授权”、精确引用或期望提交 SHA 时，同步任务必须停止并请求总控补全，不得猜测。

## 每次同步前检查

- 核对本地目标引用存在并指向授权 SHA。
- 核对远端 URL 完全一致；如尚未配置 remote，只能在本次授权范围内配置普通远端名称，不得改变其他远端。
- 只读获取目标远端引用，判断首次创建、已同步或可快进。
- 如远端包含本地没有的提交、不能快进、认证异常或网络异常，立即停止；不得 pull、merge、rebase 或强推解决。
- 核对目标提交不包含被禁止的私有资产。

## GitHub 插件的定位

- GitHub 插件可用于读取远端仓库、核对分支与提交，以及后续按用户指令处理 Issue 或 Pull Request。
- 插件提供的文件、tree、commit 和 ref API 不等同于本地 `git push`，不得用逐文件重建方式替代本地仓库的完整提交图；否则可能产生不同的提交 SHA 和两套历史。
- 保留完整本地提交历史时，唯一同步主路径是专用同步任务执行标准非强制 `git push`；插件只作为远端访问与推送后核验手段。

## 永久禁止

- 未经本次用户明确授权自动或定时 push。
- `--force`、`--force-with-lease`、`--mirror`、`--all`。
- 删除、覆盖远端分支或标签。
- 上传 Git 忽略的 APK、MDX/MDD、签名密钥、本地签名配置、数据库、缓存、恢复包或其他用户私有资料。
- 读取、记录、提交或输出 GitHub 密码、令牌、SSH 私钥或其他凭据。

## 完成回报

同步任务必须向总控回报：

- 远端 URL；
- 实际推送的本地和远端引用；
- 推送前后的远端 SHA；
- 本地授权 SHA；
- Git 命令结果；
- 是否存在未推送内容或阻塞。

总控收到成功证据后，才能向用户说明 GitHub 已更新。失败时保持本地仓库不变，并保留失败原因。

同步尝试的追加记录保存于 `_manager/GITHUB_SYNC_LOG.md`。
